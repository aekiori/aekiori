# 파일럿 설계 Red Team

## 판정

현재 설계는 `CAL-0001`을 이용한 3~5개 수작업 dry-run에는 들어갈 수 있다. 모집단 생존율 계산, 변수 효과 추정, 플랫폼 원인 주장에는 들어갈 수 없다.

## 무효화 위협과 방어선

| 위협 | 잘못된 결론 | 방어선 | 동결 통과 조건 |
|---|---|---|---|
| 사례 선택 편향 | 찾기 어려운 가게가 있는 건물을 일반 상권처럼 해석 | `CAL-*`를 교정 전용으로 격리 | 추론 통계에서 전부 제외되는 필드와 분석 규칙 존재 |
| 거리영상의 정답지화 | 간판이 보이면 법적 영업 존재로 확정 | 관측 단위를 `facade/sign observation`으로 설정 | 영업·법적 동일성을 별도 미확인 필드로 기록 |
| 판독 가능한 간판만 분모에 포함 | 가려지거나 작은 점포를 체계적으로 제거 | 공간 경계 내 모든 점포 bay를 먼저 열거 | `unreadable`, `occluded`, `vacant`, `ambiguous`도 분모 원장에 남음 |
| 정답 상호 누출 | 정확한 이름을 아는 검증을 일반 발견 능력으로 해석 | K0/K1/K2 지식 조건 분리 | 각 실행에 사용 가능했던 단서가 저장됨 |
| 사후 지식 오염 | 앞 단계 검색 결과를 다음 독립 조건의 입력으로 사용 | 단일 조사자는 누적 탐색으로만 해석; 독립 비교는 별도 블라인드 재실행 | 실행 목적이 `progressive`인지 `independent`인지 명시 |
| 행정기록 결과 누출 | 행정 DB를 결과에 넣고 인허가 업종의 우세를 발견 | 출처별 결과 벡터 사용; 행정 채널을 일반웹 결과와 합산하지 않음 | 행정기록 가설의 1차 결과가 별도 채널로 정의됨 |
| E0~E5 단일 척도 혼합 | 출처 수·계보·동일성·난이도를 한 숫자로 왜곡 | 원분석은 다차원 필드, E등급은 서술 요약만 | 모든 E등급을 원필드로 역추적 가능 |
| 검색 순서 효과 | 먼저 둔 플랫폼이 더 발견 가능한 것처럼 보임 | 출처 lane과 지식 regime별 예산·결과 저장 | `first query`를 보편적 난이도로 해석하지 않음 |
| 검색 결과 변동 | 한 번의 순위가 고정된 현실처럼 취급 | 엔진·로그인·지역·시각·상위 결과·화면 보존 | 핵심 결과는 다른 날 반복 여부가 기록됨 |
| 동일성 과잉 확정 | 같은 이름·주소만으로 같은 업소 확정 | 법적·브랜드·장소 연속성을 별도 판정 | `confirmed`는 근거 조합과 충돌 검사를 통과 |
| 출처 독립성 착각 | 같은 원자료를 복제한 두 페이지를 독립 증거로 계산 | `independence_group` 기록 | E3 등 다중 출처 주장은 독립 그룹 2개 이상 |
| 플랫폼·경로 혼합 | Google 공간영상 성공과 다른 플랫폼 텍스트 실패를 점포 하나의 성질로 축약 | 결과 단위를 `점포 × 플랫폼 × 기록형식 × 지식조건 × 조사시점`으로 유지 | 출처별 원필드 없이 단일 생존값을 만들지 않음 |
| 부정 증거 과장 | 검색 실패를 기록 부재나 존재 부재로 변환 | 모든 음성 결과를 프로토콜·시점에 결박 | `not_found_under_protocol` 외의 부재 표현 금지 |
| 조사 노력 불균등 | 집요하게 판 가게가 더 잘 살아남은 것처럼 보임 | regime별 시간·쿼리 상한과 초과 사유 기록 | 무단 초과 0건 |
| 연구자 기억 효과 | 개인 기억과 흥미가 판독·동일성 판단을 끌고 감 | 원문자열과 정규화 값을 분리; 일부 블라인드 재판독 | 최소 2개 사례 또는 20%를 재판독 |
| 개인정보 노출 | 과거 전화번호가 현재 개인 번호로 이어짐 | 원번호 비공개, 공개 산출물은 마스킹·해시 | 공개용 데이터에 원전화번호 0건 |
| 자동화 조기 도입 | 잘못 정의된 동일성·누락을 대량 복제 | 수작업 dry-run 종료 전 크롤러·자동 매칭 금지 | 반복 병목과 오류율이 문서화된 뒤 별도 승인 |

## `CAL-0001`에 대한 적대적 질문

1. `롤리팝`이 정말 상호인가, 상품 브랜드나 장식 문구인가?
2. `세계수입과자할인점`은 고유명사가 아니라 업종 설명 아닌가?
3. 점포가 촬영일에 영업한 것이 아니라 폐점 직전·직후 간판만 남아 있던 것은 아닌가?
4. 파리바게뜨 왼쪽이라는 정렬만으로 현재 화사공인중개사 자리와 같은 호수라고 할 수 있는가?
5. 이전 검색은 어떤 문자열·플랫폼·로그인 상태·날짜·예산으로 수행됐는가?
6. 행정 DB에서 못 찾은 이유가 기록 소실이 아니라 애초 수집 대상이 아니었기 때문 아닌가?
7. Google 영상 발견은 검색 성공인가, 정확한 장소를 이미 아는 사용자의 공간 탐색 성공인가?
8. 이 사례의 어려움을 건물의 다른 점포나 산본 전체에 투사하고 있지 않은가?

## 동결 전 필수 실패 시험

- 같은 간판을 일정 시간 뒤 다시 판독해 문자열·역할 판정이 유지되는지 확인한다.
- 정확한 상호를 감춘 상태에서 다른 조사자가 위치·시점만으로 후보를 찾을 수 있는지 소규모로 확인한다.
- 행정 채널을 제거해도 일반웹 발견 결과가 동일하게 기록되는지 확인한다.
- 같은 원자료를 재게시한 결과 두 개가 독립 출처로 중복 계산되지 않는지 확인한다.
- 주소만 같은 다른 업소 후보를 넣었을 때 동일성 판정이 `confirmed`로 오르지 않는지 확인한다.
- 검색 결과가 없는 사례에서 보고 문구가 자동으로 `not_found_under_protocol`에 머무는지 확인한다.

## 정지 규칙

다음 중 하나가 발생하면 전체 교정 조사를 시작하지 않고 프로토콜을 수정한다.

- 점포 bay의 공간 경계를 일관되게 열거할 수 없음
- 동일한 증거에 대한 판정이 반복 조사에서 크게 달라짐
- K0/K1/K2 사용 단서를 로그로 분리할 수 없음
- 출처별 결과를 합산하지 않고는 E등급을 부여할 수 없음
- 한 점포의 조사 시간이 상한을 반복적으로 초과함
- 원자료와 주장 사이의 provenance 링크가 누락됨

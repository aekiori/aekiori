# PILOT_PROTOCOL_V0.1

```text
status: DRAFT_UNFROZEN
created: 2026-08-11
scope: measurement calibration only
calibration_site: CAL-0001
substantive_hypothesis_test: prohibited
automation: prohibited
```

## 1. 목적

첫 단계의 목적은 과거 가게를 많이 찾는 것이 아니다. 다음을 실제 자료에서 재현 가능하게 측정할 수 있는지 확인한다.

1. 과거 공간 영상의 관측 단위를 편향 없이 열거할 수 있는가?
2. 관측된 간판과 실제 사업체 가설을 분리할 수 있는가?
3. 기록의 관측 여부와 현재 회수 난이도를 출처별로 분리할 수 있는가?
4. 조사자의 사전지식과 추가 노력에 따라 결과가 어떻게 달라지는가?
5. 동일성 판단과 음성 결과를 보수적으로 기록할 수 있는가?

## 2. 인과 과정 모형

이 모형은 현재 원인이 밝혀졌다는 주장이 아니라 관측 위치를 정하기 위한 구조다.

```text
물리적 영업 또는 간판 상태
  -> source별 기록 생성
  -> source별 보존
  -> 플랫폼 구조화·색인
  -> 조사자 지식 조건과 질의
  -> 후보 회수
  -> 동일성 판정
```

점포 특성 하나가 모든 단계에 같은 방식으로 작용한다고 가정하지 않는다.

## 3. 코호트 역할

### CAL-0001 — 측정 교정 코호트

- 위치: 사용자 제공 율곡A상가
- 기준 시점: Google 화면 표시 `2015년 7월`
- 선정 이유: 이미 알려진 어려운 최초 사례가 존재
- 사용 가능: 스키마·검색예산·판정 규칙 dry-run
- 사용 금지: 생존율·효과크기·인과 추정

### 향후 INFER 코호트

교정 완료 뒤 별도로 설계한다. 선정 시점에 개별 점포의 검색 결과를 알지 못해야 하며, 장소 선택 규칙도 결과와 독립적이어야 한다. CAL 코호트와 합산하지 않는다.

## 4. 관측 단위 계층

```text
site
  -> panorama/capture
    -> facade_bay
      -> sign_observation
        -> hypothesized_business_entity
          -> evidence_item
```

- `facade_bay`: 물리적 점포 구획 후보. 가림·공실·판독 불가도 기록한다.
- `sign_observation`: 영상에서 읽은 문자열과 시각 정황.
- `hypothesized_business_entity`: 간판이 지시한다고 추정하는 사업체. 법적 실재와 동일성을 별도로 검증한다.

거리영상은 사업체 ground truth가 아니다. 표본 원장의 1차 분모는 공간 경계 안의 모든 `facade_bay`다.

## 5. 공간 경계 봉인

외부 텍스트 검색 전에 다음을 완료한다.

1. 사용할 2015년 7월 panorama의 제공자·표시 시점·화면 또는 참조를 저장한다.
2. 조사할 건물 전면의 시작·끝 앵커를 문장과 이미지로 지정한다.
3. 경계 안의 모든 1층 bay를 왼쪽부터 번호화한다.
4. 상층 간판은 별도 층으로 번호화하며 1층 점포와 임의 결합하지 않는다.
5. 각 bay를 `occupied_candidate`, `vacant`, `occluded`, `unreadable`, `ambiguous_boundary` 중 하나로 기록한다.
6. 검색 결과를 보기 전 표본 원장의 파일 해시를 고정한다.

제공 이미지 한 장은 건물 전체 경계를 보장하지 않는다. 따라서 V0.1 dry-run은 이미지 안에서 완전히 보이는 `CAL-0001-S01`의 1층 세 bay로 축소해 봉인했다. 이는 전체 건물 표본이 아니다.

## 6. 지식 조건

### K0 — 공간·시점만 아는 발견

허용 단서:

- 건물 주소 또는 확정된 공간 앵커
- 기준 연·월
- 점포 bay 위치

금지 단서:

- 간판 상호
- 전화번호
- 검색 후 발견한 법적 명칭

### K1 — 현실적 시각 단서

K0 단서에 다음을 추가한다.

- 가려지거나 불완전한 원문자열
- 추정 업종
- 인접 점포 또는 층 정보

정규화된 정답 상호와 전화번호는 사용하지 않는다.

### K2 — 원영상에서 얻은 전체 단서

다음을 사용할 수 있다.

- 정확히 판독된 간판 문자열의 모든 역할 후보
- 영상에 보이는 전화번호
- 역사 주소와 현재 주소
- 프랜차이즈·업종 단서

K2는 `oracle-aided verification`이며 일반 발견 능력으로 해석하지 않는다.

### K3 — 사후 조사 단서

검색 중 새로 얻은 법적 명칭, 사업자 정보, 이전 주소 등이다. 계보 복원에는 쓸 수 있지만 K0~K2 발견 성능에는 소급 사용하지 않는다.

단일 조사자가 K0부터 순차 수행하면 결과는 `progressive retrieval ladder`다. K0/K1/K2를 독립 조건처럼 비교하려면 서로 결과를 모르는 별도 조사 또는 블라인드 재실행이 필요하다.

## 7. 출처 채널

각 결과는 하나의 주 채널과 원자료 독립 그룹을 가진다.

| 코드 | 채널 | 예시 역할 |
|---|---|---|
| `ANCHOR_IMAGE` | 표본을 만든 기준 영상 | 결과변수에서 제외 |
| `GENERAL_WEB` | 일반 검색엔진 결과 | 텍스트 회수 가능성 |
| `MAP_PLACE` | 현재·과거 지도 장소 항목 | 플랫폼 구조화 기록 |
| `HISTORICAL_IMAGE_OTHER` | 기준 영상 외 제공자의 과거영상 | 공간·시점 회수 |
| `ADMIN` | 인허가·공공 사업장 자료 | 행정 포착 |
| `NEWS` | 신문·보도 아카이브 | 사건성 기록 |
| `UGC` | 블로그·카페·개인 게시물 | 이용자 생성 기록 |
| `WEB_ARCHIVE` | 과거 웹페이지 보존본 | 웹 보존 |
| `DIRECTORY_OTHER` | 전화번호부·상업 디렉터리 등 | 구조화된 보조 기록 |

`ADMIN`의 성공을 다른 채널과 합쳐 “인터넷 생존” 단일 점수로 만들지 않는다.

## 8. 검색 실행 단위와 예산

각 실행은 다음을 저장한다.

- 조사자 또는 실행 주체
- 시작·종료 시각
- 지식 조건
- 출처 채널과 검색엔진
- 로그인 여부, 언어·지역, 브라우저 상태
- 입력 질의 원문
- 열람한 상위 결과 범위
- 후보 URL·제목·요약·순위
- 유효 증거로 채택 또는 기각한 이유
- 화면 또는 응답 보존 경로
- 시간 상한 초과 여부와 사유

V0.1 dry-run 예산은 점포당 최대 20분이다.

```text
K0: 최대 5분
K1: 최대 5분
K2: 최대 10분
```

K0에서 성공해도 K1/K2의 독립 성공률을 자동 생성하지 않는다. 계단식 조사에서는 최초 성공 조건과 총비용만 주 결과로 쓴다. 예산이 반복적으로 부족하면 몰래 연장하지 않고 프로토콜 수정 사유로 기록한다.

## 9. 증거와 음성 결과

유효 증거 항목에는 최소한 다음이 필요하다.

- 무엇을 주장하는 자료인지
- 원출처와 URL 또는 로컬 원본
- 자료의 표시 날짜와 회수 날짜
- 주소·전화·상호·인접 점포 등 동일성 앵커
- 다른 결과와 같은 원자료를 복제했는지 나타내는 `independence_group`
- 원문과 연구자의 해석 분리

결과가 없으면 다음처럼 쓴다.

```text
not_found_under_protocol:
  knowledge_regime: K1
  source_channel: GENERAL_WEB
  searched_at: ...
  budget_seconds: ...
  queries: [...]
```

`기록 없음`, `웹페이지가 없었음`, `존재하지 않았음`으로 승격하지 않는다.

## 10. 동일성 판정

다음 앵커를 기록하되 하나의 숫자 점수로 자동 합산하지 않는다.

- 정확한 역사 주소·호수
- 전화번호
- 고유한 상호 문자열
- 촬영·게시·인허가 날짜
- 업종
- 인접 점포와 공간 배치
- 사업자·인허가 식별자
- 이전·폐업·후속 점포의 시간 순서

판정 값:

- `confirmed`: 강한 독립 앵커 조합이 있고 물질적 충돌이 없음
- `probable`: 가장 좋은 설명이지만 하나 이상의 핵심 앵커가 미확인
- `possible`: 후보는 성립하지만 대체 후보를 배제하지 못함
- `conflicting`: 강한 증거끼리 충돌
- `unknown`: 판정할 자료 부족

법적·브랜드·장소 연속성은 각각 위 값을 가진다. 주소 일치 또는 상호 일치 하나만으로 `confirmed`를 부여하지 않는다.
전화번호 일치는 강한 앵커가 될 수 있지만 번호 승계·재사용 가능성 때문에 단독 확정 조건으로 쓰지 않는다.

## 11. 결과 변수

원분석에는 다음 벡터를 사용한다.

- 출처 채널별 `observed / not_found_under_protocol / not_searched / ambiguous`
- 최초 성공 지식 조건
- 최초 성공까지의 시간과 질의 수
- 상위 결과 노출 여부와 순위
- 모호한 후보 수
- 동일성 판정과 충돌 수
- 법적·브랜드·장소 연속성
- 주소·상호 정규화에 필요한 변환 수

E0~E5는 사람이 읽는 요약에만 사용할 수 있으며 원필드를 대체하지 않는다.

## 12. Dry-run 표본

전체 공간 원장을 봉인한 뒤 서로 다른 실패 모드를 의도적으로 포함하는 3~5개를 고른다.

- 이미 알려진 어려운 사례 1개: 롤리팝 (`prior_search_exposure=true`)
- 명확한 프랜차이즈 양성 대조 1개
- 규제 업종 후보 1개
- 일반적인 상호의 독립 소매·서비스업 후보 1개 이상

이 목적표집은 규칙을 깨뜨리기 위한 것이며 결과 빈도 계산에 쓰지 않는다.

## 13. Dry-run 성공 조건

다음을 모두 만족해야 V1.0 동결 후보로 진행한다.

1. 모든 필수 원자료와 주장이 provenance로 연결된다.
2. 모든 음성 결과가 검색 조건과 예산에 묶여 있다.
3. 간판 원문, 정규화 상호, 법적 명칭이 분리된다.
4. `GENERAL_WEB`과 `MAP_PLACE`의 1차 실행은 `ADMIN`에서 얻은 새 식별자를 보기 전에 끝나며, 행정 채널의 성공이 다른 채널의 성공으로 합산되지 않는다.
5. 어떤 사례도 주소 또는 상호 하나만으로 `confirmed`가 되지 않는다.
6. 최소 2개 사례 또는 전체의 20% 이상을 재판독해 핵심 판정의 일치 여부를 기록한다.
7. 무단 시간 초과가 없다.
8. 모호한 규칙과 변경 제안이 열거된다.

## 14. 프로토콜 변경과 동결

- V0.1 결과는 규칙 교정용이며 substantive result로 승격하지 않는다.
- 변경은 이유, 영향을 받는 필드, 기존 dry-run 재실행 여부를 기록한다.
- V1.0 동결 시 문서와 스키마의 SHA-256을 기록한다.
- 전체 교정 중 핵심 판정 규칙이 바뀌면 이전 결과와 새 결과를 같은 버전으로 합치지 않는다.

## 15. 윤리·공개 경계

- 공개된 역사적 사업장 자료만 사용하고 현재 개인에게 연락하지 않는다.
- 전화번호는 로컬 매칭 키로만 쓰고 공개 산출물에서는 마스킹 또는 비가역 해시 처리한다.
- 가정 기반 사업장, 현재 개인번호, 얼굴, 차량번호 등 불필요한 개인정보를 재배포하지 않는다.
- 플랫폼 약관과 접근 제한을 우회하지 않는다.
- 자동 크롤링은 별도 검토와 명시적 승인 전에는 하지 않는다.

## 16. 현재 정지점

`CAL-0001-S01`의 세 bay는 검색 전에 봉인됐다. 다음 실행 전 필요한 것은 각 bay에 적용할 정확한 K0/K1/K2 질의, 출처 채널 순서, 결과 열람 범위와 시간 예산을 별도 query plan으로 고정하는 것이다. 건물 전체가 포괄된다는 주장은 계속 금지한다.

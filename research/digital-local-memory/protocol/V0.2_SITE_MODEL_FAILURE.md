# V0.2 pre-retrieval site-model failure

```text
failure_id: CAL-0002-PF01
detected_at: 2026-08-11
protocol: PILOT_PROTOCOL_V0.2
phase: site inspection before scope/query-plan freeze
target_searches_executed: 0
status: FAILED_PRE_RETRIEVAL_MODEL_TEST
```

## 관측

동결된 선택 규칙의 첫 적격 후보 `candidate 21`에는 연속된 물리적 1층 facade bay 세 개가 보인다. 가운데 bay 하나에는 `김연주 헤어샵`과 `하얀크리닝`이라는 두 간판 문자열과 세탁·미용 서비스 단서가 함께 있다. 영상만으로 두 별도 사업체의 공간 공유인지, 한 사업체의 복합 서비스인지, 과거 간판 잔존인지 확정할 수 없다.

## 계약 실패

V0.2 retrieval schema는 query를 `bay_id`에만 연결하고 `bay_outcomes`에 identity 하나만 둔다. 따라서 다음을 손실 없이 표현할 수 없다.

- 한 bay의 복수 `hypothesized_business_entity`
- entity별 K1/K2 query와 결과
- 같은 bay 안에서 서로 다른 current listing·historical anchor·identity 판정
- 한 result가 어느 entity 후보를 지지하거나 반박하는지

가운데 bay의 두 문자열을 하나로 합치거나 하나를 버리면 원영상 관측을 검색 편의에 맞게 왜곡하게 된다.

## 판정과 조치

- V0.2의 site selection·상태기계·예산·privacy 규칙은 관측 자료로 보존한다.
- V0.2 schema와 validator는 수정하지 않는다.
- `CAL-0002` target query plan이나 Google/Naver 검색은 시작하지 않았다.
- V0.3에서 `facade_bay ↔ entity_hypothesis`를 분리하고 query/result/outcome을 entity ID에 연결한다.
- 이 변경 뒤 새 manifest를 검색 전에 봉인한다.

이 실패는 V0.2 결과를 사후 구제하는 변경이 아니다. 결과가 생성되기 전 관측 모형이 깨진 것이다.
